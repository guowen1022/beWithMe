## New findings

### F1 — infra imports up into silicon_brain (leaf rule broken)
- **Dimension:** D1
- **Severity:** high
- **Evidence:** `infra/devices/registry.py:31` — `from silicon_brain.models.device import Device as DeviceORM`. This is the one hit from the §3/§10 dep-graph grep that is supposed to return zero. `infra` is the leaf (invariant 1); importing `silicon_brain` inverts the one-direction rule.
- **Recommended action:** move the `Device` ORM down to `infra` (it's infra-level device registry data), or invert via a contract/DTO so `infra` doesn't name a `silicon_brain` type. Decide ownership of `Device` deliberately.
- **Status:** ✅ resolved 2026-06-15 — user confirmed device is infra-level (media→visual→canvas). Moved the ORM `silicon_brain/models/device.py` → `infra/devices/models.py`; repointed `registry.py:31`; preserved table registration in `scripts/init_db.py` + `infra/user_data.py:_MODEL_MODULES`. Leaf grep now returns zero; `test_user_data_map.py` passes (devices still in the purge map). The `users.id` FK is a metadata string reference, so no new import edge was created.

### F2 — tools/ reach into persona & service internals instead of HTTP
- **Dimension:** D1 (and D2 — this is why tools can't be unit-tested)
- **Severity:** high
- **Evidence:** `tools/read_concept_mastery.py:25` → `from persona.teacher.knowledge import get_concepts`; `tools/speak.py:34`, `tools/web_view.py:28`, `tools/app_action.py:25` → `from services.persona.routers.dynamic import enqueue_for_*`. Principle 1 says tools are typed verbs that call services over HTTP; these are in-process imports of a persona's and a sidecar router's internals.
- **Recommended action:** wrap these via the intended boundary — an HTTP call (or a thin injected port) instead of importing the router/persona module. Unlocks isolated unit tests for `tools/`.
- **Status:** ✅ resolved 2026-06-17 — root cause was bigger than 3 tools (17 sites all reaching the SSE delivery capability buried in a persona router). Fix: lifted the delivery seam (`enqueue_for_user/device`, `mounted_block_ids`, queue registry + mount tracker) out of `services/persona/routers/dynamic.py` into `infra/devices/delivery.py` (user's call: SSE is device/canvas machinery → infra); repointed all 17 importers. Moved misplaced tools to their regions per the placement rule: `read_concept_mastery` → `persona/teacher/tools/`, `app_action` → `persona/app_operator/tools/`. Closed the Issue-C/F3 *speak+canvas* slice too: `speak` reads voice prefs via `SiliconBrainClient` (new `/api/voice-preference` on the UserPreferences row), and `CanvasLayout` ORM moved to `infra/devices/canvas_layout.py` (like Device). Now **no tool imports a service/persona internal or a silicon_brain ORM**. Verified: all dep-graph greps clean, e2e SSE/canvas suite green (mount_template, media_reader, teacher_tools, speak_channels, ask_flow); also fixed a latent missing `import json` in speak.py. (Note: kickoff.py inbox_proposal — the rest of F3 — stays open.)

### F3 — persona sidecar queries silicon_brain directly
- **Dimension:** D1
- **Severity:** medium
- **Evidence:** `services/persona/routers/kickoff.py:26` — `from silicon_brain.models.inbox_proposal import InboxProposal`, then a direct `async_session()` SQLAlchemy query (kickoff.py:57–63). Invariant 7 / Principle 1: persona reaches the brain through the knowledge sidecar (`SiliconBrainClient`), not by importing a `silicon_brain` table. (Note: `InboxProposal` is a *silicon_brain* table, not a `persona/teacher/models/` table — so the "persona may query its own tables" exception does not apply.)
- **Recommended action:** read the proposal via the knowledge sidecar (add a `SiliconBrainClient` method + `infra/contracts/` DTO if missing).
- **Status:** ✅ resolved 2026-06-17 — the lone direct silicon_brain query (`_already_realized`, the kickoff idempotency check) now goes over HTTP: added `GET /api/inbox/realized` (knowledge inbox router) + `SiliconBrainClient.inbox_proposal_realized()`; `kickoff.py` dropped `from silicon_brain.models.inbox_proposal import InboxProposal` + `infra.db.async_session`/`select`, and shares one client across the K parallel checks. The **persona sidecar now imports zero silicon_brain ORM**. e2e green (inbox_and_cache + inbox_interactions + maestro = 21 passed).

### F4 — frontend has no tests at all
- **Dimension:** D2
- **Severity:** high
- **Evidence:** zero `*.test.ts(x)` / `*.spec.ts(x)` under `frontend/` (outside node_modules). Logic-bearing modules (`lib/eouGate.ts`, `lib/blockState.ts`, `lib/api.ts`) are untested; coupling runs through global event buses (`lib/bus.ts`, `lib/focusTracker.ts`), making isolation harder.
- **Recommended action:** stand up a component/unit harness (e.g. Vitest + Testing Library); start with the pure-logic libs (`eouGate`, `blockState`) which need no DOM.
- **Status:** ✅ accepted 2026-06-17 (owner decision) — frontend unit tests "cannot find anything useful"; the team covers frontend behavior via **e2e** instead. The backend e2e suite (`tests/e2e/`) already exercises the frontend's API + SSE contracts; browser-level e2e is the vehicle for UI coverage. P2 (self-contained = testable) is satisfied for the frontend at the **e2e layer**, not the unit layer. A recorded coverage-strategy decision, not a code change.

### F5 — desktop (Electron) has no unit tests
- **Dimension:** D2
- **Severity:** medium
- **Evidence:** no `desktop/**/*.test.ts`; `desktop/src/main.ts` BrowserView/WebContents logic is hard to mock; preload logic (`preload-browser.ts` viewport gathering) is pure JS but uncovered. Only partial coverage via the Python e2e suite.
- **Recommended action:** extract the pure preload/probe logic behind testable seams and cover it; keep Electron-context glue thin.
- **Status:** ✅ accepted 2026-06-17 (owner decision) — same as F4: desktop/Electron behavior is covered via **e2e**, not unit tests. Recorded decision, not a code change.

### F6 — oversized modules hurt readability at the margins
- **Dimension:** D3
- **Severity:** low
- **Evidence:** `persona/teacher/contexts/answer.py` `assemble()` ~180-line body (numbered phases help, but it mixes retrieval + orchestration); `services/persona/routers/ask.py` ~31KB; `services/browser/main.py` ~41KB single-file action dispatcher; `services/maestro` state machines (`gate.py`, `long.py`) reference SPEC §5.4 only in docstrings.
- **Recommended action:** decompose the largest handlers into named helpers/submodules; add inline SPEC references at the decision points in maestro. Low urgency — these are readable today, just dense.
- **Status:** ✅ resolved 2026-06-17 — disassembly executed per [`../proposals/2026-06-17-F6-module-disassembly.md`](../proposals/2026-06-17-F6-module-disassembly.md). `ask.py` **735→426** (+`_ask_addressee.py` for the `/block`+app_operator routing, +`_ask_voice.py` with an `AutoSpeakBuffer` for the inlined auto-speak state machine); `browser/main.py` **1138→103** (+`session.py`, +`snapshot.py`, +`browse.py`, +`web_view_routes.py`); `answer.py` **293→88**, `assemble()` now a ~40-line orchestrator over `_answer_parts.py`. Pure refactor — no wire/contract/SSE/tool-order change; **33 e2e green** (ask_flow, speak_channels, mount_template, test_e2e incl. browser), leaf grep clean, both sidecars import.
